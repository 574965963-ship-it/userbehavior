# 淘宝用户行为数据 · 转化漏斗分析

> 基于阿里天池公开数据集（约 1 亿行）的完整漏斗分析：从数据清洗、口径设计到业务洞察，围绕一个业务问题展开——**转化漏斗的流失点在哪、怎么优化？**

## 项目简介

对淘宝 2017-11-25 ~ 12-03 共 9 天、**100,150,807 行**用户行为日志做数据清洗与漏斗分析，定位转化流失环节，并给出建议。

**核心结论**：76% 的购买是"看中就买"的直接决策，94% 的加购/收藏最终未成交——购物车/收藏夹召回是最大的增量机会。

## 数据来源

- **数据集**：阿里天池公开数据集（dataset 649）

- **字段结构**（5 列，按顺序）：

| 字段 | 类型 | 含义 |
|---|---|---|
| user_id | INT UNSIGNED | 用户ID|
| item_id | INT UNSIGNED | 商品ID|
| category_id | INT UNSIGNED | 类目ID|
| behavior_type | VARCHAR(10) | 行为类型：`pv`浏览 / `cart`加购 / `fav`收藏 / `buy`购买 |
| ts | INT UNSIGNED | Unix 秒级时间戳 |

## 技术栈

- **MySQL 8.0**（`LOAD DATA` 导入 1 亿行、`COUNT(DISTINCT)` 多列去重、`CASE WHEN` 分流、子查询/临时表）
- **SQL**：数据体检 → 清洗 → 漏斗/品类/时段/决策路径四类分析
- **Excel 图表**：条形图、散点图、柱线组合图、饼图）

## 核心发现

| 分析 | 关键数字 | 洞察 |
|---|---|---|
| **整体漏斗** | 浏览 7100 万 → 意向 826 万 → 购买 193 万对（去重用户-商品对）| 浏览→购买仅 **2.71%**，流失最大在"浏览→意向"第一层 |
| **决策路径** | **76.1% 购买是直接买**，未经过加购/收藏 | 用户"看中就买"，应优化"浏览→下单"顺畅度 |
| **召回机会** | 加购/收藏后成交仅 **5.58%**，即 **94.4% 意向未召回** | 780 万个"加了购物车却走掉"的用户是精准营销对象 |
| **品类黑洞** | TOP10 品类吃掉 **27.7% 流量，转化仅 0.93%**（整体 2.71%）| 头部品类在浪费流量，需流量再分配 |
| **时段陷阱** | 流量峰在 21~22 点，但转化率峰在 10~12 点 | 晚上是"逛"的高峰、"买"的低谷，需分时段运营 |

## 分析方法论

定口径

1. **计数用"去重用户-商品对"**，不是"事件数"——同一用户重复浏览同一商品，`COUNT(*)` 会虚高，`COUNT(DISTINCT user_id, item_id)` 才是正确粒度。
2. **漏斗有"分支"**——粗暴算"购买/意向 = 23.33%"是错的（它假设所有购买都经过了加购/收藏），实际 **76% 购买是直接买**。正确口径是分支漏斗，严格口径为 **5.58%**。
3. **数据体检**——清洗前先摸清脏数据规模（5.5 万行越界时间戳，占 0.055%），用一条 WHERE 按官方时间窗口过滤

## 执行步骤

1. **建表**：ID 字段用 `INT UNSIGNED NOT NULL`（省空间，且排除 NULL/负数的空值形式）
2. **导入**：开启 `local_infile` 后 `LOAD DATA LOCAL INFILE` 导入 1 亿行，行数与官方一致
3. **体检**：验证行为类型只有 4 种、时间范围、缺失/非法值
4. **清洗**：过滤掉时间戳越界的 5.5 万行（0.055%），建 `userbehavior_clean` 表，同时把 ts 转成日期
5. **分析**：按四个子问题依次写 SQL
